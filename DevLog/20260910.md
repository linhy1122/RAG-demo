## 二、多轮问答 RAG + 会话记忆

### 2.1 核心实现

**双 ChatClient 装配**

- 主 `chatClient`：挂 `MessageChatMemoryAdvisor`，负责正式回答与记忆写入。
- `rewriteChatClient`：手动构建，无 Advisor，仅用于查询改写，避免污染正式记忆。

**记忆写入路径**

- 路径①：主 ChatClient 成功时由 Advisor 自动写入。
- 路径②：跳过主 LLM 的兜底轮，手动写入 user + 话术 A/B。
- 路径③：仅当 gate 证明 Advisor 空回复跳过写入时，手动写入 user + 话术 C。

**条纹锁**

- ask / history / clear 共用 64 条纹锁，保证同会话串行，避免读写中间态。

**动态上下文预算**

- `chunkBudget = context-max-chars - historyChars - systemChars - 用户问题长度`
- 预算耗尽后不再追加切片，走话术 B。

**source 可追溯**

- Milvus schema 新增 source 字段，search 返回 source。
- 入库时取文件名、null 兜底 unknown、256 字符粗截，保证 UTF-8 字节 ≤ 1024。

### 2.2 Gate 四项结论

| Gate | 结论 | 影响 |
| ---- | ---- | ---- |
| ① Advisor 异常时写入行为 | 异常前 user 已写入记忆，形成孤立 U | ask 异常路径已实现回滚 |
| ② Advisor 空回复时写入行为 | 写入 [U, A_empty]，话术 C 不重复写入 | §6.5 方案 B 成立：空 reply 不移除 |
| ③ ChatMemory API 面 | 仅 add/get/clear，内存窗口实现可用 | 按计划使用 |
| ④ Customizer 拾取 | RestClientCustomizer 未被 OpenAI 自动配置拾取 | 改用 OpenAiHttpClientBuilderCustomizer 设置读超时，`rag.chat.timeout-seconds=60` 生效 |

## 三、召回正文详细日志增强

### 3.1 实施内容

先恢复完整基线 commit `05e4d6b`，再叠加日志改动。新增配置：

```properties
rag.chat.log-retrieval=true
rag.chat.log-retrieval-max-raw=10
```

新增 `[chat-retrieval]` INFO 日志：

- **摘要行**：sessionId, rewritten, threshold, rawHits, usedRefs, embedCostMs, searchCostMs, retrievalTotalMs
- **raw 行**：过滤前 topK 命中，打印 id/score/source/passedThreshold/text
- **used 行**：实际入 Prompt 的切片，打印 id/score/source/text
- 正文按 `chunk-max-chars` 截断；raw 超上限打“raw 省略 K 条”
- 调用顺序统一：`logRetrieval → logTurn → return`

### 3.2 计划外调整

- **raw 行补正文**：真实联调发现 raw 只有元数据不满足“打印被召回文档内容”需求，改为 raw 与 used 都带正文。
- **Milvus 显式降序排序**：`search()` 返回前按相似度降序，保证 raw[1] 最相似、回答引用 [1] 对应最相似切片。
- **修正访问器**：`ChatAnswer.SourceItem` 使用 `id()` 而非 `chunkId()`。

### 3.3 测试结果

- 新增 U16（threshold=1.0）、U17（maxRaw=0）、U18（日志开关关闭）三个边界测试。
- 最终 mvn verify：45 个测试全绿，BUILD SUCCESS，JaCoCo 门槛通过。
- 边界无 NPE：
  - `score-threshold=1.0` 走兜底 A；
  - `log-retrieval-max-raw=0` 只打省略行；
  - `log-retrieval=false` 无 `[chat-retrieval]` 行。

## 五、关键决策与经验

- 兜底话术必须按语义区分，不能复用“知识库中没有相关内容”掩盖预算耗尽。
- 空 reply 不删除记忆：窗口淘汰不可逆，残留空 assistant 影响小于丢失最早对话；该结论依赖 gate②“写入型”结论。
- 预算机制只保证“预算耗尽后不再追加切片”，不声称总 prompt 不超限；真正 token 级历史裁剪列入暂不做。
- 召回日志默认开发开启，生产建议覆盖为 false，避免正文含身份证、手机号、邮箱、API Key 等敏感信息。
- 相似度排序必须显式化，不能依赖 Milvus 默认返回顺序。
