需求：基于状态机的 Markdown 文档结构解析与语义分块
一、目标
实现一个基于状态机（Finite State Machine, FSA）的 Markdown 文档解析器，用于将非结构化的长文本按标题层级切分为独立的语义块（List<T>），并提取特定区域的结构化数据（如表格、简谱）。最终输出结果需适配后续存入 Milvus 等向量数据库的需求。

二、 核心架构与状态定义
解析器需要维护一个状态变量，并在读取每一行时进行状态评估和流转。核心状态包括：TITLE（标题）、TABLE（表格）、MUSIC_SCORE（曲调）、TEXT（正文）。

1. 状态流转与语义分块（List<T> 逻辑）

初始状态： 逐行读取文本。

标题识别（进入 TITLE 状态）：

检测行首是否以 # 开头。

记录当前标题级别（一级 #、二级 ##、三级 ### 等）和标题内容。

状态机动作（触发快照）： 遇到新标题时，结束当前累积的语义块，将当前 List<T> 的内容打包输出（如存入 Milvus），然后清空 List<T>，以新标题为起点重新开始累积。

正文累积（进入 TEXT 状态）：

若不以 # 开头，且不属于表格或曲调，则视为正文内容，追加到当前的语义块（List<T>）中。

2. 特殊区域状态与处理

表格区域（进入 TABLE 状态）：

进入条件： 识别到 Markdown 表格标志（如连续行包含 | 和 ---，例如 | ---- | ---- |）。

状态机动作： 记录当前处于“表格区域”。表格内容不作为普通文本累积，而是作为结构化数据单独提取。

退出条件： 遇到下一个标题（#）或其他非表格行，状态切换回 TITLE 或 TEXT。

曲调区域（进入 MUSIC_SCORE 状态）：

进入条件： 满足下述“曲调识别与防误判规则”。

状态机动作： 标记该行为“曲调行”。该行内容不累积到普通文本的 List<T> 中（或作为特殊的元数据单独存储），避免污染正文语义。

三、 曲调识别与防误判规则（核心难点）
在识别简谱（曲调）时，必须避免将电话号码、日期或 Markdown 表格分隔符误判为曲调。判定规则必须满足以下所有条件：

强制包含音乐专有符号：

必须包含小节线 | 或 独立延音线 -（前后带空格的横线）。

防误判： 如果一行只有数字、点、空格（如 0592-6181301 或 138 1234 5678），直接判定为非曲调。

严格的字符白名单：

仅允许数字 0-9、点 .、竖线 |、短横 -、空格。

防误判： 出现字母（除调号外）、括号、冒号、连续的短横线（如 --- 分隔符）等一律排除。

上下文依赖（前置条件检测）：

曲调通常出现在特定上下文中。若前 3-5 行内出现了调号（如 1=F、1=G）或拍号（如 2/4、4/4），则后续包含 | 和数字的行极大概率是曲调。

若突然出现一行无上下文的数字，降低判定优先级。

优先级约束：

表格状态（TABLE）的优先级高于曲调状态。如果当前行符合 Markdown 表格特征，直接归入表格，不进行曲调检测。

正则约束：

匹配曲调的正则表达式必须要求数字和 | 交替出现，且不能匹配纯数字串（如 13812345678）。
